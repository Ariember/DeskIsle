# DeskIsle 插件协议 v1

插件是独立运行的发布者。它负责访问目标软件、处理授权和决定何时更新。DeskIsle 通过版本化的扩展点接收结果，执行该扩展点约定的行为。当前宿主实现了 `desktop.cards` v1，负责桌面磁贴的排版与展示。任何能启动进程或写本地文件的语言都能接入。

## 进程接口

在当前 Windows 用户下调用 `deskisle.exe`。这些命令在桌面程序关闭时也可使用。调用方应重定向标准流、等待进程退出并检查退出码。

| 调用 | 行为 | 成功返回 |
| --- | --- | --- |
| `plugins list` | 列出所选市场提供的插件 | 标准输出为 JSON 数组，每项含 `id`、`name`、`version`、`description` |
| `plugins install <id>` | 从同一市场取包、校验并安装，已有同 ID 内容时替换 | 退出码 0 |
| `plugins capabilities` | 查询这个可执行文件支持的协议和扩展点版本 | 标准输出为能力表 JSON |
| `plugins validate <id> [文件路径]` | 按当前宿主能力校验完整发布文档，不写文件 | 标准输出为含 `name`、`version` 的 JSON 对象 |
| `plugins publish <id> [文件路径]` | 注册或更新一个插件，原子替换该 ID 的整份发布文档 | 退出码 0 |
| `plugins remove <id>` | 撤下该 ID 的全部发布内容。重复撤下也成功 | 退出码 0 |

`validate` 和 `publish` 省略文件路径时从标准输入读取 UTF-8 字节直至 EOF。参数错误、协议不受支持、校验或存储失败时，进程以退出码 1 结束，原因写入标准错误。失败的发布保留原有版本。退出码表示本地保存操作的结果，桌面呈现由运行中的宿主异步完成。

能力查询返回形如 `{"protocol":1,"points":{"desktop.cards":[1]}}` 的对象。发布者应按扩展点名检查版本数组，在双方支持的版本中选择一个。新增条目时，已有客户端可以忽略自己用不到的条目。

## 身份与发布文档

ID 由命令参数指定，在文件接口中对应文件名。选用稳定的发布者前缀，例如 `vendor-feature`。ID 长度为 1 至 64，须匹配 `^[a-z0-9][a-z0-9-]{0,63}$`。保留名称为 `con`、`prn`、`aux`、`nul`、`com0` 至 `com9`、`lpt0` 至 `lpt9`。ID 在当前用户下共享。两个进程写同一 ID 时，最后一次成功替换生效。

下面展示协议数据的形状，可直接保存为 UTF-8 文件并传给 `plugins validate`。

```json
{
  "protocol": 1,
  "name": "发布者名称",
  "version": "1.0.0",
  "contributions": [
    {
      "point": "desktop.cards",
      "version": 1,
      "data": {
        "cards": [
          { "title": "指标名称", "value": "42", "detail": "单位或更新时间" }
        ]
      }
    }
  ]
}
```

| 发布字段 | 约定 |
| --- | --- |
| `protocol` | 外层协议版本，当前为整数字面量 `1`。无法识别时拒绝整份发布 |
| `name` | 插件显示名称，1 至 64 个字符，单行且不能全为空白 |
| `version` | 发布者自身的 SemVer 版本字符串。宿主依据扩展点版本选择数据契约 |
| `contributions` | 一组扩展声明，最多 16 项；每个扩展点名只能出现一次。空数组合法 |

每份文档最多 65,536 字节，使用 UTF-8，可带 BOM。外层及已实现的扩展结构均拒绝未知字段。可用[协议 JSON Schema](plugins.schema.json)做编辑器提示或结构检查。最终以 `plugins validate` 为准，它还会检查宿主能力、插件 ID 和扩展点重名等条件。

## 扩展声明与兼容性

每项声明均包含 `point`、`version` 和 `data`，可附带 `required`。`point` 需匹配 `^[a-z][a-z0-9-]*(\.[a-z][a-z0-9-]*)+$`，全长最多 64 个字符。`version` 是 1 至 4,294,967,295 的整数，由该扩展点独立编号。`data` 的含义由该点在指定版本的契约定义。

| 宿主检查结果 | 处理 |
| --- | --- |
| 支持点名和版本，数据合法 | 交给该扩展点处理 |
| 支持点名和版本，数据不合法 | 拒绝整份发布，防止部分更新 |
| 点名或版本未知，`required` 为 `true` 或省略 | 拒绝整份发布 |
| 点名或版本未知，`required` 为 `false` | 跳过该项，继续处理其他声明，保存的文档保留原始内容 |

新增一种宿主能力时，为它分配稳定的点名，定义数据格式、大小限制、权限、失败行为、更新与撤下语义，并在宿主注册表中登记支持的版本。`capabilities` 与运行时校验使用同一份注册表。已有扩展点的破坏性数据或行为变更使用新版本号；外层协议仅在通用字段或生命周期契约变化时升级。插件作者可以组合已注册的扩展点。引入宿主尚未实现的动作，需要同时提供相应的宿主处理逻辑。

## 已实现的扩展点

### `desktop.cards` v1

`data` 为 `{"cards":[…]}`。单个插件最多发布 16 张，数组顺序即显示顺序，空数组清空该插件的磁贴。多个发布者按 ID 排序。

| 卡片字段 | 约定 |
| --- | --- |
| `title` | 必填，1 至 64 个字符，作为标题 |
| `value` | 必填，1 至 64 个字符，作为主读数。发布者负责将数字、单位或状态格式化为字符串 |
| `detail` | 可选，最多 160 个字符，默认空字符串 |
| `state` | 可选，默认 `ready`。`ready` 为正常展示，`setup` 表示需要用户配置，`error` 表示数据不可用。发布者可在主读数或详情里写明下一步操作 |

文本按 Unicode 标量计数，必须为单行，不能包含控制字符、U+2028 或 U+2029。标题和主读数至少包含一个非空白字符。

## 存储、运行与撤下

发布成功后，数据一直有效，直到该 ID 再次发布或撤下。插件退出不会删除数据。具有时效性的指标可在详情中注明采样时间，取数失败可发布 `error` 状态，卸载时调用 `remove`。宿主只解释已注册的数据格式。第三方服务的网络访问、凭据、后台调度和进程启停由发布者管理。当前协议不启动发布者程序，也不执行文档中的命令。

发布命令与文件接口共用 `%APPDATA%\DeskIsle\plugins\<id>.json`。直接写文件的工具应按需创建目录，在**同一目录**用唯一的 `.tmp` 文件写完并关闭，再通过系统的原子替换操作发布到最终文件名。撤下时删除对应 JSON 文件。宿主只扫描扩展名为小写 `.json` 的普通文件。目录是当前用户数据，不提供同一用户下不同进程间的访问隔离；发布文档只应包含准备交给宿主展示或处理的数据。

开启桌面卡片后，宿主立即读取一次，此后在每轮读取结束约三秒后再读。直接写入的损坏文件按插件单独显示错误，其余发布者继续展示。桌面为空时没有占位卡，关闭「管理面板 → 插件」的“显示桌面卡片”会停止读取并隐藏磁贴；已经发布的数据仍会保留。

## 从插件市场安装

在「管理面板 → 插件」可查看已安装的本地插件与卡片状态，并浏览插件市场一键安装、更新或移除桌面卡片。面板安装与移除后立即刷新桌面卡片，重新启动 DeskIsle 后也会加载。安装与外部发布共用同一 ID 和文件，后一次成功写入的内容生效。也可使用命令行 `deskisle.exe plugins remove <id>` 卸载。

市场使用 `index.json` 列出包，每个条目对应索引旁的 `packages/<id>.json`。宿主先校验索引，再按条目的 SHA-256、名称、版本和当前宿主支持的扩展点校验包。校验或下载失败时会返回错误，已有卡片可继续使用。

管理面板和命令行默认向 GitHub 查询 `Ariember/DeskIsle-PluginMarket` 的最新稳定 Release，按其 `v<SemVer>` 标签读取仓库根目录的索引。点击安装时，宿主从刚才浏览的标签读取卡片包，因此市场在浏览后发布新版也不会改变这次安装的内容。[市场发布页](https://github.com/Ariember/DeskIsle-PluginMarket/releases)

要测试本地改动或使用自建市场，在启动 DeskIsle 前将 `DESKISLE_MARKET_INDEX` 设为本地索引文件路径或完整的 HTTPS 索引 URL。设置后直接读取指定索引。在线托管时，索引和包的地址均需直接返回文件内容及 HTTP 200。下面的 PowerShell 示例从两个项目的父目录运行。

```powershell
$env:DESKISLE_MARKET_INDEX = (Resolve-Path '.\DeskIsle-PluginMarket\index.json').Path
.\DeskIsle\target\release\deskisle.exe plugins list | ConvertFrom-Json
```
