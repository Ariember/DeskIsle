# Dock 架构

DeskIsle 面向 Windows 11，以独立桌面进程运行。使用 Rust stable 的 MSVC 工具链，通过 `windows` crate 调用 Win32、DirectComposition 和 D3D11。退出时释放本进程创建的资源，系统任务栏继续沿用用户设置。

## 目录与模块边界

DeskIsle 是单个 Cargo 应用。根目录的 `Cargo.toml` 声明依赖，`Cargo.lock` 锁定版本。`AGENTS.md` 记录开发规范，`docs/` 记录技术选型与架构决策。

`src/main.rs` 调用 `app::run`，报告启动或运行错误并返回退出状态。代码按四层组织，使同一条交互流程中的布局、业务决策和系统操作可以分别修改和验证。

| 层次 | 现有路径 | 职责 |
| --- | --- | --- |
| 展现层 | `src/ui/`、`src/render/` | UI 用纯 Rust 值描述双栏、菜单和设置面板的布局、命中区域和可选命令，`ui/panel.rs` 还负责面板的焦点、滚动和翻页。渲染器读取这些值，管理 DirectComposition 图层、图标、菜单与面板表面及动画。 |
| 应用层 | `src/app/` | `mod.rs` 持有双栏及其资源，调度事件与刷新。`menus.rs` 管理弹窗交互和暂存事件。`commands.rs` 执行选择、固定、激活等命令。`settings.rs` 打开设置面板、分派其输入，并让每项改动生效、保存。 |
| 领域层 | `src/dock.rs`、`src/settings.rs` | `dock.rs` 根据固定项、窗口快照和前台标识分组，选择启动、激活或列出窗口。`settings.rs` 以 `SCHEMA` 表声明每项设置的分组、控件、取值范围、默认值和存放位置，并负责校验与调整。使用路径、标识和值类型表达规则，单测可直接构造输入。 |
| 适配层 | `src/platform/`、`src/storage/` | 平台负责 Win32 消息与窗口、显示器和 AppBar，`shell.rs` 负责窗口跟踪与 Shell 操作，`tray.rs` 负责托盘宿主和点击转发，`startup.rs` 读写当前用户的开机启动项。存储负责固定项、托盘隐藏设置和 `settings.ini` 的文件格式、读写及错误转换。 |

应用层可调用其余三层。展现层和适配层通过领域值交换数据，均不依赖应用层。`src/geometry.rs` 中的 `Rect` 是平台、应用与界面共用的像素矩形，系统的 `RECT` 在平台边界转换。领域模块不依赖窗口、渲染或文件系统。

新增使用统计或可见性策略时，独立的纯规则可分别放在 `usage`、`visibility`。接入独立外部服务时再创建 `src/integrations/`。启动时检查前台应用的客户区是否覆盖主屏，运行中由 AppBar 全屏通知控制双栏显隐。

首版在主显示器上下各建一个独立合成窗口。Dock 运行时隐藏 Explorer 的主任务栏，副屏沿用系统任务栏。顶部状态栏横跨显示器全宽，以 AppBar 注册并预留顶部条带，最大化窗口排在其下方，全屏应用出现时隐藏。状态栏左侧显示前台应用，点击可打开应用列表或退出；右侧依次为托盘图标、溢出按钮和本地时间。底栏在主屏工作区底部居中。隐藏任务栏后，如果工作区底边紧贴该任务栏，DeskIsle 将主屏系统工作区延伸到屏幕底边，已最大化的窗口也随之调整。底栏默认固定文件资源管理器和任务管理器，按进程映像路径聚合其他可见窗口。固定项由用户在图标菜单中增删，按可执行文件路径逐行写入 `%APPDATA%\DeskIsle\pins.txt`；文件不存在时使用默认固定项，读取失败时提示并使用默认项，用户再次修改时才覆盖。图标下方标记区分运行和前台状态；空间不足时可用滚轮浏览。

## 右键菜单

菜单内容取决于点击目标。Dock 图标和状态栏上的前台应用名弹出该应用的菜单：窗口列表（标出前台窗口）、打开或新建窗口、打开文件所在位置、固定或取消固定，有窗口时再列出关闭。左键点击多窗口应用时只列出它的窗口。时钟弹出日期、通知和日历以及日期和时间设置。溢出按钮列出未显示的托盘图标和逐项显示开关。托盘图标的右键照常转发给所属应用。两栏空白处和状态栏标志弹出应用列表、任务管理器、显示桌面和退出。

菜单不使用 `TrackPopupMenu`。两栏是 `WS_EX_NOACTIVATE` 窗口，无法稳定成为前台，原生菜单因此常常一闪即关，点击别处也关不掉。DeskIsle 改为自建一个可激活的置顶弹窗：打开时取得前台，失去激活、按 Esc 或 Alt、点击阴影区时关闭。点击两栏不会改变激活状态，因此菜单循环把两栏的按下事件当作点击别处处理：左键只关闭菜单，并吞掉随后的松开事件；右键关闭后，松开事件照常弹出新目标的菜单。若 Windows 拒绝激活菜单，就在前台窗口发生变化时关闭。菜单打开期间，两栏收到的其他事件先暂存，关闭后按原顺序处理，因此菜单命令引用的应用列表和托盘序号在此期间保持不变。命令执行前按应用标识和窗口句柄重新核对目标。

菜单背景、阴影和文字在打开时各绘制一次。悬停只更新高亮图层的位移和透明度，打开时的淡入和缩放也交给合成器执行，静止时没有重绘。图形设备在菜单期间失效时，菜单关闭，并沿用两栏的设备重建流程。

Windows 11 未提供读取通知区域的接口。`Shell_NotifyIcon` 把通知以 `WM_COPYDATA` 发给 `FindWindow` 找到的第一个 `Shell_TrayWnd`，因此平台层创建一个同类名的隐藏窗口，并置于 Explorer 任务栏之上。它复制收到的图标，再把每条消息原样转发给 Explorer 自己的 `Shell_TrayWnd`，以桌面窗口所属进程识别，避免与其他托盘宿主互相转发。系统托盘照常工作，DeskIsle 退出后应用也无需重新注册图标。启动时广播 `TaskbarCreated`，让应用重新添加图标。以管理员权限运行的应用收不到该广播，其图标在下次更新时出现，DeskIsle 发给它们的点击也会被 UIPI 拦截并报错。隐藏窗口同步 Explorer 任务栏的矩形，按 `Shell_TrayWnd` 定位弹窗的应用仍能放对位置。

托盘图标左键、右键按图标声明的版本转发为对应回调消息。溢出菜单列出用户隐藏和放不下的图标，“在状态栏显示”子菜单逐项切换显示。隐藏项以“可执行文件路径 + 图标 GUID 或 ID”为键，写入 `%APPDATA%\DeskIsle\tray-hidden.txt`。文件不存在时全部显示；读取失败时提示并全部显示，用户再次切换时才覆盖。

新职责先在所属模块内实现。拆分子模块时按调用方使用的职责命名，例如 Shell 调用在 `platform/shell.rs`，设置读写在 `storage/`。读取失败后的回退与提示由应用层统一决定。

模块单测就近放在 `#[cfg(test)]` 中。需要从公开入口跨模块验证的场景放入 `tests/`。随程序分发的静态资源放入 `assets/`，需要重复执行的开发或测量脚本放入 `scripts/`。这些目录随第一个实际文件创建。

## 设置面板

状态栏标志或两栏空白处的菜单中选“设置”，打开设置面板；面板已打开时只把它提到前台。面板是普通的可激活窗口，带标题栏样式，因此 DWM 提供阴影、圆角和 Alt+Tab 入口。客户区覆盖整个窗口，标题栏、导航和控件都由 DeskIsle 自绘，标题区以 `HTCAPTION` 交给系统拖动。Dock 不列出本进程的窗口，所以面板不提供最小化，用关闭按钮、Esc 或 Alt+F4 关闭。面板是非模态的：事件进入主循环，与两栏共用同一 UI 线程和图形设备。只有输入改变布局时才重绘，打开后静止时没有开销。设备重建后，面板随两栏重新绑定。

左侧按 `SECTIONS` 列出分页，右侧按 `SCHEMA` 中属于当前分页的行生成卡片。控件有开关、步进器和分段选择三种。内容超出窗口时可用滚轮滚动；键盘用 Tab 或上下键移动焦点，左右键调整，空格或回车切换，Ctrl+Tab 或 PageUp/PageDown 翻页。每页底部的“恢复默认”只重置本页。

改动立即生效并保存，没有确认步骤。应用层逐项比较新旧设置：Dock 尺寸和间距改变时重新布局，悬停放大在下次悬停时生效，隐藏任务栏改变时立即隐藏或交还任务栏并重新计算工作区，开机启动写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。系统拒绝某项改动时报告错误，并把该项恢复为原值，其余改动照常生效。

文件型设置以 `id = value` 逐行写入 `%APPDATA%\DeskIsle\settings.ini`，`#` 开头的行为注释。文件不存在时使用默认值。读取失败时提示并使用默认值；某一行无效时提示并只让该项回到默认值。用户再次修改时才覆盖文件。未知的键会被忽略，以兼容较新版本写入的文件，但下次保存时不会保留。开机启动的实际状态由注册表决定：启动时读取，只有指向当前可执行文件的启动项才算启用。

新增一项设置的步骤：

1. 在 `settings.rs` 的 `Key` 中加入变体，在 `SCHEMA` 中加入一行，写明 `id`、分组、说明、控件、默认值和存放位置。需要新分页时同时加入 `Section` 和 `SECTIONS`。需要给调用方用的类型值时，加一个访问方法。
2. 在 `app/settings.rs` 的 `apply_settings` 中处理该键变化后的效果。编译器会要求覆盖新变体。
3. 面板、文件读写、校验和恢复默认无需改动。`settings.rs` 的单测会检查 `id` 唯一、默认值合法以及读写往返一致。

## 职责与数据流

以点击 Dock 图标为例，平台把指针事件交给应用层。应用层用 UI 布局命中对应图标，重新枚举窗口，再用领域模块的 `group_apps` 和 `AppGroup::action` 决定动作。启动或激活交给 Shell 适配器，多窗口选择交给菜单。操作完成后，应用层刷新快照并把新布局和活动状态交给渲染器。

渲染器根据布局创建合成图层。图标内容或缩放密度变化时更新纹理，指针移动时只提交受影响图层的变换。静止且状态稳定时不安排重绘。

启动时先订阅窗口事件，再枚举可见的应用窗口。回调将变化投递到 UI 消息循环，由 UI 线程查询最新状态、更新应用分组，再向合成器提交变化。重复通知按当前窗口状态归并，前台标记以系统实际前台窗口为准。

点击图标时，按应用标识查找窗口。没有窗口则启动应用，单窗口直接切换，多窗口先供用户选择。执行前复核目标的存在性和应用身份，仅对已最小化窗口执行还原。若目标已关闭，刷新窗口列表。若系统拒绝激活，保留实际活动项。

## 资源与恢复

同一登录会话只运行一份 Dock。隐藏系统任务栏前，`platform/taskbar.rs` 将 Explorer 的进程号和任务栏窗口句柄写给恢复进程。释放底部条带前，Dock 也会将这项操作告知恢复进程。正常退出时 Dock 核对窗口归属，恢复任务栏及其底部占位，再释放会话互斥对象。主进程被强制终止时，系统会关闭管道，由恢复进程执行同一项还原。Explorer 重启后按新窗口接管。

创建 Dock 窗口的 UI 线程负责消息循环、COM 初始化和合成提交。窗口回调只投递需要的事件，避免在可重入调用期间持有可变状态。取得所有权的图标和系统资源按各自 API 契约释放。退出时先撤销事件订阅，再释放合成对象、销毁窗口，最后反初始化 COM。

布局以设备无关单位计算，定位和点击命中使用目标显示器的有效 DPI。收到 DPI、工作区或显示拓扑变化通知后，重新查询显示器。原显示器消失时回到主屏工作区。顶部条带只在 Shell 通知位置变化、显示器边界或 DPI 改变时重新协商，避免每次工作区通知都再次触发调整。Explorer 重启后重新注册 AppBar、把托盘宿主重新置顶并重新枚举窗口，应用随 `TaskbarCreated` 重新添加图标。前台变化后也会重新置顶托盘宿主，因为 Explorer 激活任务栏时会把它提到前面。所属窗口已关闭的托盘图标在窗口事件后移除。图形设备失效时保留应用状态，重建设备、表面和图层。若重建失败，报告失败的操作和系统错误码。

## 行为验证

用布局测试覆盖混合缩放、工作区偏移与图标命中边界。真机验证窗口选择期间目标关闭、最大化窗口切回、Explorer 重启和拔掉副屏后的行为。托盘部分验证图标增删与动态图标刷新、左右键菜单、隐藏设置跨重启保留，以及与其他占用顶部或托盘的桌面工具共存时的表现。分别记录静置时的 CPU 占用与连续悬停时的帧时间，并注明硬件、刷新率和缩放比例。
