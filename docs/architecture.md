# Dock 架构

DeskIsle 面向 Windows 11，以独立桌面进程运行。使用 Rust stable 的 MSVC 工具链，通过 `windows` crate 调用 Win32、DirectComposition 和 D3D11。退出时释放本进程创建的资源，系统任务栏继续沿用用户设置。

## 目录与模块边界

DeskIsle 是单个 Cargo 应用。根目录的 `Cargo.toml` 声明依赖，`Cargo.lock` 锁定版本。`AGENTS.md` 记录开发规范，`docs/` 记录技术选型与架构决策。

`src/main.rs` 调用 `app::run`，报告启动或运行错误并返回退出状态。代码按四层组织，使同一条交互流程中的布局、业务决策和系统操作可以分别修改和验证。

| 层次 | 现有路径 | 职责 |
| --- | --- | --- |
| 展现层 | `src/ui/`、`src/render/` | UI 用纯 Rust 值描述双栏、菜单和设置面板的布局、命中区域和可选命令，`ui/panel.rs` 还负责面板的焦点、滚动和翻页，`ui/system.rs` 决定状态栏系统图标的显示与各弹出面板的内容，`ui/icon.rs` 是全应用共用的图标集，以纯值描述每个图标的轮廓。渲染器读取这些值，管理 DirectComposition 图层、`render/glass.rs` 液态玻璃表面与 `render/prism.rs` 玻璃材质着色、图标、菜单与面板表面、明暗调色板及动画。 |
| 应用层 | `src/app/` | `mod.rs` 持有双栏及其资源，调度事件与刷新。`menus.rs` 管理弹窗交互、滑块拖动和暂存事件。`commands.rs` 执行选择、固定、激活等命令。`preview.rs` 管理悬停预览的保活过渡、点击激活与关闭窗口。`settings.rs` 打开设置面板、分派其输入，让每项改动生效、保存，并按主题设置切换调色板。`system.rs` 刷新系统状态、打开系统面板并执行其中的改动。`about.rs` 打开关于卡片并分派其输入。 |
| 领域层 | `src/dock.rs`、`src/settings.rs`、`src/system.rs`、`src/metrics.rs`、`src/machine.rs` | `dock.rs` 根据固定项、窗口快照和前台标识分组，选择启动、激活或列出窗口。`settings.rs` 以 `SCHEMA` 表声明每项设置的分组、控件、取值范围、默认值和存放位置，并负责校验与调整。`system.rs` 定义声音、电源、显示器、无线电和媒体的状态快照及百分比换算。`machine.rs` 描述关于卡片展示的本机信息，并决定处理器、图形卡、内存和 Windows 版本的措辞。使用路径、标识和值类型表达规则，单测可直接构造输入。 |
| 适配层 | `src/platform/`、`src/integrations/`、`src/storage/` | 平台负责 Win32 消息与窗口、显示器和 AppBar，`shell.rs` 负责窗口跟踪与 Shell 操作，`tray.rs` 负责托盘宿主和点击转发，`startup.rs` 读写当前用户的开机启动项。`machine.rs` 从注册表、DXGI、内存状态和 SMBIOS 读取关于卡片的本机信息，`about.rs` 管理关于卡片的窗口。`audio.rs`、`power.rs`、`display.rs`、`network.rs`、`media.rs` 分别读写音量与输出设备、电池与电源计划（并执行睡眠、重启、关机、注销和锁屏）、亮度/HDR/系统明暗、Wi-Fi 与蓝牙、媒体会话。存储负责固定项、托盘隐藏设置和 `settings.ini` 的文件格式、读写及错误转换。 |

应用层可调用其余三层。展现层和适配层通过领域值交换数据，均不依赖应用层。`src/geometry.rs` 中的 `Rect` 是平台、应用与界面共用的像素矩形，系统的 `RECT` 在平台边界转换。领域模块不依赖窗口、渲染或文件系统。

独立的使用统计规则可放在 `usage`，外部服务适配代码归入 `src/integrations/`。启动时检查前台应用的客户区是否覆盖主屏，运行中结合 AppBar 通知和前台窗口判断是否全屏。顶栏在全屏时隐藏。`src/visibility.rs` 按全屏、桌面、前台窗口与 Dock 的相交情况以及热键状态决定底栏显示、收起到底边或完全隐藏，并给出所选模式的窗口层级。

首版在主显示器上下各建一个独立合成窗口。Dock 运行时隐藏 Explorer 的主任务栏，副屏沿用系统任务栏。顶部状态栏横跨显示器全宽，以 AppBar 注册并预留顶部条带，最大化窗口排在其下方，全屏应用出现时隐藏。状态栏最左侧为 DeskIsle 标志，单击打开系统菜单（见“右键菜单”）；其后显示前台应用，点击可打开应用列表或退出；右侧依次为托盘图标、溢出按钮、资源监控、系统图标和本地时间，系统图标见“状态栏系统面板”。底栏在主屏工作区底部居中。隐藏任务栏后，如果工作区底边紧贴该任务栏，DeskIsle 将主屏系统工作区延伸到屏幕底边，已最大化的窗口也随之调整。底栏默认固定文件资源管理器和任务管理器，按进程映像路径聚合其他可见窗口。用户通过拖放或图标菜单固定应用，按住图标可左右调整固定顺序。固定区可插入多条分割线，与应用共用拖动排序。`app/drag.rs` 按应用标识或分割符的固定位置跟踪拖动，使用布局给出的落点预览顺序，松手后保存。`%APPDATA%\DeskIsle\pins.txt` 按显示顺序每行记录一个固定项。应用记录原始启动路径，分割符单独记为 `|`；文件不存在时使用默认固定项，读取失败时提示并使用默认项，用户再次修改时才覆盖。图标下方标记区分运行和前台状态；空间不足时可用滚轮浏览。

鼠标移入底栏程序图标时，应用层按该程序的窗口列表打开置顶预览。同一程序的多个窗口按比例排在图标上方，每张卡片顶部显示窗口标题和右上角关闭按钮，下方由 DWM 合成实时缩略图。指针从底栏图标穿过间隙移入预览小窗期间保持预览和自动隐藏/智能隐藏底栏展开，移出底栏和预览后关闭并按模式收起底栏。点击预览卡片还原并激活对应窗口，点击右上角关闭按钮向该窗口投递标准关闭请求。启动台和没有窗口的固定程序不显示预览。`ui/preview.rs` 按工作区和 DPI 布置卡片、关闭按钮、命中区域与过渡桥接区，`render/preview.rs` 用同一套 Direct2D/DirectWrite 管线离屏绘制卡片外观，`platform/preview.rs` 管理不激活的交互式预览窗口和 DWM 缩略图注册，`app/preview.rs` 协调悬停过渡、点击激活与关闭。

## 启动台

Dock 首位的启动台按钮打开主屏状态栏与 Dock 之间的独立窗口。窗口由 DirectComposition 绘制深色半透明背景，保留 Alt+Tab 入口，方便切回资源管理器取文件。Dock 和启动台窗口在 UI 线程注册 OLE 文件拖放目标。`platform/drop_files.rs` 识别拖入的文件，将进入、移动、离开和投放转成应用事件，同时支持原有的 `WM_DROPFILES` 投放消息。拖入 Dock 时，布局在固定区预留一个空位，渲染器沿用排序动画移动图标；松手时按当前预览命中落点。拖到启动台按钮或窗口时，按钮抬起，打开的启动台显示接收提示。`app/drag.rs` 检查文件类型和可访问性。落在 Dock 应用区的文件按应用身份与启动路径去重后固定，普通无参数程序快捷方式可以按目标程序匹配运行窗口。落在启动台按钮或启动台窗口的文件交给 `app/launchpad.rs`，按原始路径忽略大小写去重；启动台关闭时也能添加。点击项目时将原路径交给 Shell，快捷方式的参数和工作目录由 Windows 读取。

`ui/launchpad.rs` 根据可用空间、DPI 和搜索文字计算可见图标及分页。绘制、点击、悬停和右键移除共用这份布局。启动台项目保存在 `%APPDATA%\DeskIsle\launchpad.txt`，按拖入顺序每行记录一个路径。首次打开时文件缺失对应空列表。保存成功后才更新界面，读取失败会提示并保留原文件。

## 插件与桌面卡片

`app/plugin_cli.rs` 在桌面单实例检查前分派能力查询、校验、发布或撤下命令。`plugins.rs` 负责插件元数据、扩展点注册、版本匹配和输入校验。每个新扩展点在此声明并交给对应模块处理。`integrations/plugins.rs` 按插件 ID 原子替换或移除发布文档。发布者的接口见[插件协议 v1](plugins.md)。

开启桌面卡片时，`app/cards.rs` 在后台读取 `desktop.cards` 内容，仅在数据变化时通知界面线程。关闭显示时停止读取，退出时先撤销工作线程的窗口通知目标。`ui/cards.rs` 按主屏工作区和 DPI 计算卡片、分页和命中范围。`platform/cards.rs` 管理不激活的桌面窗口，`render/cards.rs` 使用已有图形设备绘制当前页。

## 资源监控

`platform/metrics.rs` 读取 Windows 系统计数器、内存和显卡温度。`integrations/core_temp.rs` 以只读方式打开当前会话的 Core Temp 共享区，校验固定前缀、核心数量和温度单位，取最高有效核心温度。温差模式或缺少有效传感器时返回空值。

`app/monitor.rs` 根据顶栏实际可见的项目配置后台线程。每轮采样结束后等待两秒，所有项目关闭或顶栏全屏隐藏时释放计数器并等待配置改变。采样期间配置改变会丢弃过期结果，消息只通知 UI 线程取走最新快照。`metrics.rs` 保存曲线最近 30 次观测，缺失值在曲线上留空。`render/metrics.rs` 在独立合成图层上绘制图标和读数，采样更新只重绘监控区域。

## 状态栏系统面板

状态栏右侧在资源监控与时钟之间依次显示网络、显示器、电池（仅在有电池时）、声音和控制中心。网络图标区分 Wi-Fi、有线和蜂窝连接。音量图标显示静音状态和音量档位，`IMMNotificationClient` 通知默认播放设备的变化，DeskIsle 随后将 `IAudioEndpointVolumeCallback` 绑定到新设备。电池按 `WM_POWERBROADCAST` 通知更新电量和供电状态。时钟每分钟触发一次网络刷新，打开网络面板或控制中心及关闭系统面板时也会刷新。

状态栏、菜单、系统面板和设置面板的图标统一取自 DeskIsle 自绘的线性图标集（见“图标集”），左侧标志为圆环，命中区域为距左缘 4–32 DIP 的槽位。标志位于顶部栏之上的独立合成层，由圆环和中心实心圆点两个子层组成：系统菜单打开时圆环在 0.22 秒内轻按回弹，圆点从中心以缓出曲线长到 2.5 DIP 半径；菜单关闭后圆点在 0.16 秒内收回，再执行所选命令。动画只改变合成器缩放变换，不重绘顶部栏；中途切换从圆点当前大小继续。状态栏右侧各项的槽位宽度等于内容宽度加 12 DIP 间隔，内容居中，槽位首尾相接：托盘图标、溢出按钮、资源监控、系统图标、时钟和关闭按钮的可见内容彼此相隔同一距离，指针落在两者之间也总会命中其一。图标按 16 DIP 计，电池按 22 DIP 计；时钟按当前字体测量“00:00”，数值型监控按三位数读数测量并右对齐，读数变化不会挤动相邻项目。`ui/layout.rs` 通过调用方传入的测量函数取得文字宽度，应用层传入渲染器的 DirectWrite 测量，字体、字号或粗体设置改变后重新布局。电池不再显示百分比，电量只由图标填充表示，具体数值在电池面板中查看。指针悬停的标志、托盘图标、溢出按钮、系统图标和时钟背后显示一块浅色圆角底板，面板打开期间该图标的底板加深。溢出按钮是列表图标：收起时为主色的项目符号列表，溢出菜单打开期间换成实心圆角底板上反白的列表，与菜单中“开启用实心底”的约定一致。功能不可用的系统图标（未联网、没有音频设备）以 55% 不透明度绘制，在浅色栏上仍有约 3:1 的对比度。悬停状态随 `WM_MOUSEMOVE` 更新，只在目标变化时重绘顶部栏。

左键点击系统图标会弹出对应面板，右键直接打开对应的 Windows 设置页（`ui/system.rs` 的 `settings_page`）。在声音图标上滚动滚轮按每格 2% 调节音量，触控板的小幅滚动累计满一格再生效；调低时保持静音，调高时取消静音。中键点击声音图标切换静音，中键点击 Dock 图标新开一个实例，与 Windows 任务栏一致。状态栏其他位置的滚轮不再滚动 Dock。

状态栏的系统面板、时钟、溢出菜单以及 Dock 图标和前台应用名的菜单都使用 `ui/menu.rs` 的 `DROPDOWN_WIDTH`（320 DIP）作为固定宽度，过长的文字以省略号结尾。面板沿用自绘菜单的窗口与事件循环，新增分组标题、滑块、并排的开关卡片和媒体行：

- 声音：音量滑块（点击左侧图标切换静音）和全部活动输出设备，选中项即默认设备。
- 电池：电量、电源状态和电源计划列表。电池不报告电量时只显示电源状态。每个电源计划按用途配图标：节能为叶片；静音、平衡和高性能为点亮到指针处的仪表盘，指针依次指向左上、正上和右上；卓越性能和 Turbo 为火箭；用途不明的计划为闪电。Windows 自带的计划按 GUID 识别；复制出的计划和厂商计划 GUID 不同，再按名称不区分大小写识别：“卓越 / Turbo / 野兽 / 极速 / 增强”为最高档，“Silent / Quiet / 静音 / 安静”为静音，其后依次为“节能 / 省电 / Saver / Eco”“性能 / Performance”“平衡 / 均衡 / Balanced”。最高档的词先于“性能”判断，因为“卓越性能”“Turbo Performance”也含有它。规则在 `system.rs`，便于独立测试。
- 显示器：亮度滑块（仅 DDC/CI 显示器）、深色模式和 HDR（主显示器支持时）。
- 网络：Wi-Fi 和蓝牙开关，只列出本机具备的无线电；有线连接时另列一行以太网状态。同类设备中只要有一个可控无线电已开启，开关就显示开启。切换会作用于该类型的所有可控设备。
- 控制中心：Wi-Fi、蓝牙、深色、专注、投影卡片，亮度（仅 DDC/CI 显示器）和音量滑块。有媒体播放时再显示上一首、播放/暂停和下一首，没有播放时不留占位行。

面板中的系统改动不关闭面板：命令执行后重新查询状态，在原窗口内无动画地重建内容，窗口按新尺寸重新定位。打开设置页的条目照常关闭面板。滑块按下时捕获指针，松开时结束拖动，即使松开位置在面板外也不关闭面板。音量随拖动实时生效。亮度要通过 DDC/CI 与显示器通信，一次往往要几十毫秒，所以只在松开时写入。每个滑块是单独的合成图层，拖动时只重绘这一块表面。系统拒绝的改动会在面板上方弹窗报告。

方向键可依次选中面板中的按钮和滑块，回车或空格执行按钮命令。滑块获得焦点时，左右键按五个百分点调节。设备拒绝写入后，滑块重新读取设备状态。`platform/system_worker.rs` 在后台串行执行网络和媒体请求，无线电授权由 UI 线程发起。完成消息到达后，面板显示设备返回的状态。用户正在拖动滑块时，面板等到松开后再重新布局。

系统功能的接入方式与限制：

- 默认输出设备：使用 Windows 未公开文档的 `IPolicyConfig`，与系统声音面板相同；其 vtable 布局自 Windows 7 起未变。
- 亮度：仅支持 DDC/CI 显示器。多数笔记本内置屏不支持，面板不显示亮度滑块。
- 系统暗色模式：写入 `Personalize` 下的 `AppsUseLightTheme` 与 `SystemUsesLightTheme`，并在后台线程广播 `ImmersiveColorSet`，避免响应慢的窗口卡住 UI 线程。
- Wi-Fi 与蓝牙：开关通过 WinRT `Windows.Devices.Radios`，用户可在隐私设置中拒绝。SSID 取自当前 Internet 连接配置的名称，无需定位权限。
- 专注助手：Windows 未提供切换接口，卡片打开对应设置页。电池健康度也未提供公开接口，暂不显示。
- 睡眠命令通过 `GetPwrCapabilities` 查询电源能力。若 `AoAc` 表明系统支持 S0 现代待机，DeskIsle 向自己的栏窗口投递 `SC_MONITORPOWER` 关屏请求，由 Windows 按电源策略进入低功耗状态。传统睡眠启用 `SeShutdownPrivilege` 后调用 `SetSuspendState`。
- 重启与关机启用 `SeShutdownPrivilege` 后调用 `ExitWindowsEx`，注销调用同一接口，无需该特权。这些命令允许有未保存工作的应用阻止操作并提示。锁定屏幕调用 `LockWorkStation`。

## 图标集

`ui/icon.rs` 的 `Symbol` 列出 DeskIsle 自己绘制的全部图标：状态栏的网络、显示器、电池、音量和控制中心，各弹出面板的开关、滑块与媒体按钮，菜单命令，以及设置面板的分页与监控项。界面代码只引用 `Symbol`，不再写字体码位；新增图标时在同一文件补一个变体和它的轮廓。

每个图标画在 24 单位的网格上，主体落在 2–22 单位内，使用圆头端点和圆角连接，矩形与折线转角统一倒圆。线宽随绘制尺寸变化，约为尺寸的 1/12，限定在 1.25–2.25 DIP 之间，让 12 DIP 的菜单图标在 100% 缩放下不发虚，30 DIP 的监控图标也不显粗。同一排的状态栏图标共用一个线宽，电池画得更大以便在栏高内看清电量。音量按档位点亮声波，未点亮的声波保留淡色；电池按电量实心填充，电量不高于 15% 且未充电时以危险色填充。充电时叠加闪电，闪电与填充按异或合并：重叠处镂空，其余部分实心，填充的边缘在闪电处仍然可辨。展开的溢出列表按钮也用同样的方式，从实心底板中镂空出列表。异或在 `render/canvas.rs` 中以 Direct2D 几何合并实现，镂空处透出栏背景，不依赖背景颜色。

轮廓是纯 Rust 值（直线、二次曲线和圆弧），可在单元测试中检查是否越出网格。渲染器在 `render/canvas.rs` 用绘制该表面的 Direct2D 设备上下文所属的工厂生成路径几何并描边或填充，和其他表面内容一起在状态变化时绘制一次，不随指针移动重绘。

## 明暗主题

顶部状态栏默认使用液态玻璃（清透玻璃，斜面折射壁纸并带 RGB 色散，边缘菲涅尔反射与高光），配合带柔和阴影的文字与图标；也可在设置中切换为自上而下淡出的深色半透明渐变遮罩或纯透明样式。底部 Dock 绘制圆角矩形液态玻璃底板（圆角不超过 20 DIP），活跃应用指示点向底沿投射柔和漫射光晕。文字、图标和运行标记在背景之后绘制，各自保留原有透明度。

托盘图标默认以灰度绘制（“显示彩色托盘图标”关闭时）。应用常按任务栏主题提供浅色或深色图标，换到相反明暗的栏上会几乎看不见，所以渲染器绘制前读取图标像素：若在浅色栏上暗于中灰、或在深色栏上亮于中灰的部分不足覆盖面积的三分之一，就把它的灰阶压到远离栏色的 56% 区间，最浅（或最深）处与调色板栏色仍有约 3:1 的对比度，图标内部的明暗关系保持不变；其余图标照原样去色。栏的明暗按主色判断，沉浸模式下随窗口标题栏颜色切换。彩色模式保留应用原色，不做调整。

双栏、菜单、系统面板和设置面板共用浅色与深色调色板。设置面板仿照 macOS 系统设置：侧栏贯通整个窗口高度，各页用渐变彩色图标标识，以用户选择的强调色标示当前页；内容区的相关设置排在同一张圆角卡片中，以缩进分隔线隔开，开关、分段选择、滑块和按钮也采用 macOS 的控件样式。面板的色调定义在 `render/panel.rs`，按调色板的明暗选取。侧栏的毛玻璃使用 DWM 的系统背景 `DWMSBT_TRANSIENTWINDOW`（亚克力），模糊窗口后方的内容，接近 macOS 侧栏的透视效果。DWM 只在扩展进客户区的边框内绘制背景，所以面板只把左侧边框扩展到侧栏宽度；若扩展到整个窗口，DWM 会在右上角另画一组系统标题按钮。DPI 变化时随窗口尺寸一起更新扩展宽度。DeskIsle 只在侧栏上叠一层浅色半透明色调。Windows 11 22H2 之前的版本不接受该属性；系统“透明效果”关闭时 DWM 只画一块纯色。这两种情况下侧栏都改画不透明渐变，透明效果的读取失败也按关闭处理。切换透明效果时 Windows 广播 `WM_SETTINGCHANGE`，面板随主题检查一起重绘侧栏。窗口失去焦点时，DWM 自行把亚克力换成纯色。模糊由 DWM 持续合成，面板本身仍只在输入时重绘。“常规”页提供跟随系统、浅色、深色和自动四种颜色模式。自动模式按本地时间在 18:00 切换深色，次日 06:00 恢复浅色。用户可选择将明暗变化同步到 Windows。跟随系统时读取 `AppsUseLightTheme`，读不到时按 Windows 默认的浅色处理。Windows 切换应用模式时会广播 `WM_SETTINGCHANGE`，双栏随显示刷新流程重新判断主题。调色板改变时，渲染器丢弃顶部栏、Dock 背景和图标图层的缓存，设置面板立即重绘，DWM 边框也随之切换明暗。

“主题”页按界面分组保存独立开关和参数。应用层将已提交的设置传给渲染器，更新材质并使相关缓存失效。顶部栏、Dock、菜单、标签、启动台、设置侧栏和关于本机卡片默认在系统“透明效果”开启时绑定 `render/glass.rs` 的液态玻璃层。材质照搬 PrismGlass Desktop 的“经典液态”预设（`glass-renderer.js`，静止状态，不含指针悬停与 Astro 效果）：`render/prism.rs` 以纯 Rust 逐像素复现其着色器，经圆角 SDF 斜面按 IOR 1.46±0.065 分通道折射，叠加菲涅尔环境反射和左上方向的细高光。结果由同一 `HWND` 下层的 `Windows.UI.Composition` 显示。Dock 和下拉菜单的斜面采样窗口后方的实际画面，取样范围向外延伸以保留边缘折射。采样已显示的窗口时先由 DWM 临时隐藏它，避免把上一次的玻璃和图标画进斜面。斜面只叠加重现折射颜色所需的最小不透明度，向平坦部分渐变至全透明。后方页面滚动或播放视频时，由系统持续合成。平坦部分下方垫一层系统实时模糊的后景（`HostBackdropBrush`），透明度取模糊强度设置（未自定义时为 30%），采样到的后景明暗起伏大时再加至多 25%，上限 85%。每次采样同时测量玻璃下方后景的相对亮度：亮于黑白文字对比度相等的分界（0.179）时用浅色调色板的深色文字与图标，否则用深色调色板的浅色文字；已有选择时须越过 0.12 / 0.26 才切换，避免在分界附近来回闪烁。Dock 只在跟随主题的外观下自动调整分隔线和运行指示点，用户选定浅色或深色外观时保持不变；菜单的文字、图标、悬停底板和滑块都随之调整，截图回退时按截图测量。菜单打开及重新定位时采样；Dock 展开、切换前台窗口、覆盖它的前台窗口移动结束或标题改变，以及系统通知桌面设置变化时重新采样。其余玻璃表面按屏幕位置折射壁纸。壁纸由 `platform/wallpaper.rs` 经 `IDesktopWallpaper` 读取各显示器的图片与契合方式、用 WIC 解码后按显示器缓存；`PaintDesktop` 画入内存 DC 在当前 Windows 11 上会失败，不再使用。贴着显示器边缘的玻璃向屏幕外延伸，只在内侧露出斜面。顶部栏的壁纸调色浓度决定壁纸采样色与基础栏色的混合比例，最大化窗口的沉浸配色优先。Dock 图标与镜像共用栅格化内容，倒影的模糊、衰减及位移限定在底部留白内。

窗口预览因兼容 DWM 缩略图保留重定向位图，打开时在平台层做清晰背景采样，并以同一 `render/prism.rs` 材质绘制液态玻璃面板，采样以外的折射重复边缘像素；启动台在壁纸快照模式下同样如此。实时液态玻璃不可用时回退至静态光学采样或系统背景，系统关闭“透明效果”时退回纯色渐变。背景采样随所属窗口释放。固定到 Dock 的文件夹在点击时由 Shell 适配层枚举一层内容，用菜单列出可打开的文件和目录。分页容量和行高随所选文件图标尺寸调整。

## 右键菜单

菜单内容取决于点击目标。Dock 图标和状态栏上的前台应用名弹出该应用的菜单：窗口列表（标出前台窗口）、打开或新建窗口、打开文件所在位置、固定或取消固定，有窗口时提供“关闭窗口”，向该应用的前台窗口或 Z 序最靠前的窗口投递标准关闭请求，多窗口时显示目标标题。“退出程序…”打开对应进程的托盘菜单，由用户选择应用的退出命令。没有可用托盘菜单时，“退出程序”逐一核对该组窗口的身份并请求关闭所有窗口。应用自行处理保存提示、驻留和退出。左键点击多窗口应用时只列出它的窗口。时钟弹出日期、通知和日历以及日期和时间设置。溢出按钮列出全部应用托盘图标，并在每行切换该图标是否显示在状态栏。托盘图标的右键照常转发给所属应用。两栏空白处和右键状态栏标志弹出应用列表、任务管理器、显示桌面和退出。左键单击状态栏标志弹出系统菜单，分组列出关于本机、管理面板、Windows 设置、应用商店、任务管理器、显示桌面，睡眠、重新启动、关机，以及锁定屏幕和注销；其中会结束会话的重新启动、关机和注销按危险命令显示。菜单定位在标志下方，宽度为 220 DIP。“关于本机”打开 DeskIsle 自绘的关于卡片（见“关于本机”），不再直接跳转 Windows 设置。

菜单不使用 `TrackPopupMenu`。两栏是 `WS_EX_NOACTIVATE` 窗口，无法稳定成为前台，原生菜单因此常常一闪即关，点击别处也关不掉。DeskIsle 改为自建一个可激活的置顶弹窗：打开时取得前台，失去激活、按 Esc 或 Alt、点击阴影区时关闭。点击两栏不会改变激活状态，因此菜单循环把两栏的按下事件当作点击别处处理：左键只关闭菜单，并吞掉随后的松开事件；右键关闭后，松开事件照常弹出新目标的菜单。若 Windows 拒绝激活菜单，就在前台窗口发生变化时关闭。菜单打开期间，两栏收到的其他事件通常先暂存，关闭后按原顺序处理。托盘下拉列表会接收新注册和移除通知，按注册记录维持焦点；鼠标按下期间延后更新列表，松开时核对目标。Dock 菜单执行窗口命令前按应用标识和窗口句柄重新核对目标。

菜单背景、阴影和文字在打开时各绘制一次。悬停只更新高亮图层的位移和透明度，打开时的淡入和缩放也交给合成器执行，静止时没有重绘。图形设备在菜单期间失效时，菜单关闭，并沿用两栏的设备重建流程。

菜单面板圆角为 16 DIP，悬停高亮是一块与面板圆角同心的液态玻璃胶囊底板。行内的图标、选项和窗口标记都画在直径 24 DIP 的圆形底板上：命令图标用浅色底，危险命令用红色调；选项开启、前台窗口和保留在状态栏的托盘图标用实心底（浅色主题为深色），不再使用勾号。菜单标题的图标同样使用圆形底板。应用菜单标题的副标题显示“前台”或“未运行”。已固定的应用只有托盘菜单可用时显示“后台运行”。窗口数量和固定状态由下方的列表和命令体现。

平台层创建一个类名为 `Shell_TrayWnd` 的隐藏窗口，并置于 Explorer 的任务栏之上。`Shell_NotifyIcon` 经 `WM_COPYDATA` 通知宿主，宿主复制图标，再将注册通知转发到桌面窗口所属进程的任务栏。

启动及 Explorer 重启时，宿主读取当前用户的 `Control Panel\NotifyIconSettings` 作为候选清单。GUID 项通过 `Shell_NotifyIconGetRect` 核实仍在托盘。使用数字 ID 的项还需按程序路径匹配当前顶层窗口或消息专用窗口，并用窗口句柄和 ID 核实。只将核实过的项并入清单，实时注册负责补充回调、版本和最新图像。系统缺少该缓存时，宿主仍可接收实时通知。

主循环能够响应后，宿主广播 `TaskbarCreated`，并向消息专用窗口定向请求补注册。快照只恢复展示信息。启动或 Explorer 重启两秒后，若仍有图标只有快照或部分更新，宿主重新置顶并向相应应用再请求一次。打开溢出列表时也会补查。同一轮按窗口去重，收到完整注册或明确的回调设置后停止为该图标请求。按照 [NOTIFYICONDATAW 的约定](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw)，应用通过 `NIF_MESSAGE` 提供回调消息号后，宿主才向注册窗口异步投递点击。缺少回调的图标在栏上悬停时和溢出菜单中标为“仅显示”，仍可切换常驻。回调补齐后恢复交互。手势中途撤销或改变回调时丢弃剩余输入，保留未读标记。权限限制等投递错误在顶部栏短暂显示。

接管主屏任务栏时，隐藏宿主使用顶部栏的屏幕矩形。应用通过 `Shell_NotifyIconGetRect` 查询图标位置时，宿主按 GUID 或窗口句柄和图标 ID 返回栏上对应槽位的屏幕坐标和尺寸。折叠到溢出菜单中的图标使用溢出按钮的位置。用户保留系统任务栏、顶部栏因全屏隐藏、图标未注册或请求格式未知时，位置查询交给 Explorer。

栏和下拉菜单的窗口按系统双击设置接收鼠标消息。宿主将实际按下、双击和松开按图标注册的协议版本转发，即使图标所属进程已在前台也照常发送。键盘选择走对应的激活回调。应用据此决定打开、隐藏、切换窗口或显示菜单。鼠标松开前若图标已被替换，宿主放弃此次操作。右键回调继续使用顶部栏下沿的菜单锚点。

发送右键回调后，托盘宿主短暂观察该进程在锚点附近显示的原生、Qt 或无边框自绘弹窗。宿主监听该进程的窗口位置变化。应用可能在菜单打开后再次定位，连续右键也可能复用同一个可见窗口。宿主按图标注册信息重新确认这个窗口，跟踪到菜单隐藏、销毁或操作取消。菜单向上超出可见区域时，宿主将它移至栏下沿，保留大小、焦点和层级。

启动快照和实时注册共用系统项过滤规则。宿主按图标 GUID 或专用通知窗口类识别 Windows 安全中心、系统蓝牙、安全删除硬件、打印队列、系统语言栏等状态项。状态栏和溢出菜单只接收可见的应用图标。原始托盘消息照常转发给 Explorer。

应用发出托盘气泡或反复交替图标时，DeskIsle 在状态栏用静态圆点提示，并保留可见的图标帧。左键点击栏上图标或从溢出菜单打开应用，会确认当前提醒。后续气泡、闪烁期间更新的消息提示文字或停顿后新一轮闪烁都可再次触发提醒。Windows 托盘不提供统一的未读数，如果应用在连续播放相同动画时没有发来可区分的新信号，DeskIsle 会继续沿用已确认状态。

溢出菜单逐行列出全部应用托盘图标，不论其当前是否在状态栏上。菜单打开前重新查询 Explorer 补齐缺项，并处理已到达的托盘通知。图标较多时，按显示器 DPI 和顶部栏下方的可用高度分页，用上一页、下一页、滚轮或 Page Up / Page Down 浏览。切换常驻状态后保留当前页。每行以应用名称为标题，名称取自可执行文件版本信息中的产品名或文件说明，没有时取首个提示文字的第一行，再没有时取文件名；当前提示文字（例如 Clash 客户端显示的实时网速）合并成一行，与名称不同时以灰色小字显示在右侧，过长时以省略号结尾，至多占行宽一半。点击行左侧的圆形图标（包括其周围的留白）切换该图标是否保留在状态栏：保留时底板为实心深色，隐藏时为浅色底；菜单保持打开，便于连续切换。网速文字、图像或常驻状态变化时，只重画当前页有变化的行，保留悬停高亮；行数变化时重新布局。点击行内其余部分与点击状态栏上的图标一致：左键激活应用，右键（或菜单键、Shift+F10）请求应用自己的菜单。图标在状态栏上时以其槽位为锚点，否则使用溢出按钮的下沿锚点。保留但放不下的图标仍显示实心底，并继续经溢出菜单访问。隐藏项以“可执行文件路径 + 图标 GUID 或 ID”为键，写入 `%APPDATA%\DeskIsle\tray-hidden.txt`。文件不存在时全部显示。读取失败时提示并全部显示，用户再次切换时才覆盖。

新职责先在所属模块内实现。拆分子模块时按调用方使用的职责命名，例如 Shell 调用在 `platform/shell.rs`，设置读写在 `storage/`。读取失败后的回退与提示由应用层统一决定。

模块单测就近放在 `#[cfg(test)]` 中。需要从公开入口跨模块验证的场景放入 `tests/`。随程序分发的静态资源放入 `assets/`，需要重复执行的开发或测量脚本放入 `scripts/`。这些目录随第一个实际文件创建。

## 自动更新

`app/updates.rs` 在启动和时钟事件中调度稳定版检查。自动检查默认开启，运行期间间隔 24 小时；用户可在“常规”中关闭，也可在“关于”页立即检查。自动与手动检查共用进行中的请求。网络请求、下载和准备重启在后台执行。手动检查反馈最新状态或错误，后台检查只在发现新版时提示。

`integrations/updates.rs` 读取项目 GitHub Release 的标签和 Windows x64 资产，按语义版本判断是否升级。用户确认后才下载 `deskisle.exe`，并核对发布记录中的字节数与 SHA-256。`platform/update.rs` 在当前可执行文件旁暂存更新，启动辅助进程。辅助进程就绪后，主循环正常退出并释放任务栏资源。辅助进程替换原路径的文件，尝试启动新版；若系统拒绝启动，则尝试还原并重启旧版。此流程沿用原路径的开机启动项和用户配置目录。

## 关于本机

关于卡片仿照 macOS 的“关于本机”：左上角只有红色关闭按钮，其下依次为本机插图、计算机名、型号，以及处理器、图形卡、内存和版本四行，底部的“更多信息”打开 `ms-settings:about` 并关闭卡片。插图按 SMBIOS 机箱类型画成笔记本或显示器，读不到机箱类型时以有无电池判断。每次打开卡片时重新读取信息：计算机名取 DNS 主机名，型号取固件的 `SystemProductName`（占位文字视为缺失，再退到 `SystemFamily`），处理器取注册表中的名称与标称主频，图形卡取 DXGI 中专用显存最多的硬件适配器（跳过软件与虚拟适配器，小于 512 MB 的显存不显示），内存取 Windows 可用的物理内存，并从 SMBIOS 首个已安装的内存条读取频率与类型。Windows 11 的 `ProductName` 仍写作 Windows 10，因此版本按内部版本号区分 Windows 10 与 11，版本名按 `EditionID` 译为中文，末尾附上内部版本号与修订号。读不到的项不显示，单项失败不影响卡片打开。

`ui/about.rs` 以 DIP 计算卡片布局：标签右对齐，取值按单词换行到取值列，卡片高度随行数变化。卡片窗口沿用设置面板的做法：保留标题栏样式以获得 DWM 阴影、圆角和 Alt+Tab 入口，客户区覆盖整个窗口。卡片不带系统菜单，因此 DWM 不会在整窗扩展的亚克力背景上绘制标题栏按钮；除关闭按钮和“更多信息”外，整张卡片都可拖动。系统不支持亚克力或关闭透明效果时改画不透明渐变。Esc、Alt+F4 和关闭按钮关闭卡片，回车或空格等同“更多信息”。卡片只在悬停目标、主题、DPI 变化或设备重建时重绘。

## 设置面板

左键单击状态栏标志后选择“管理面板”，或在标志的右键菜单、两栏空白处的菜单中选择“设置”，均可打开同一面板。面板已打开时将其提到前台。面板是普通的可激活窗口，带标题栏样式，因此 DWM 提供阴影、圆角和 Alt+Tab 入口。客户区覆盖整个窗口，标题栏、导航和控件都由 DeskIsle 自绘，标题区以 `HTCAPTION` 交给系统拖动。Dock 不列出本进程的窗口，所以面板不提供最小化，用关闭按钮、Esc 或 Alt+F4 关闭。窗口按钮仿照 macOS 位于标题区左上角：红色关闭按钮可点击，悬停时显示叉号；最小化与缩放按钮以灰色显示为不可用。标题区除关闭按钮外都交给系统拖动。面板是非模态的：事件进入主循环，与两栏共用同一 UI 线程和图形设备。只有输入改变布局时才重绘，打开后静止时没有开销。设备重建后，面板随两栏重新绑定。

左侧按 `SECTIONS` 列出分页，右侧按 `SCHEMA` 中属于当前分页的行生成分组列表中的各行。数值滑块在捕获鼠标后预览位置，松手提交并保存，捕获中断或按 Esc 时放弃本次拖动。主题预览、强调色圆点和分段控件共用选择型设置。内容超出窗口时可用滚轮滚动；键盘用 Tab 或上下键移动焦点，左右键调整，空格或回车切换，Ctrl+Tab 或 PageUp/PageDown 翻页。设置页底部的“恢复默认”只重置本页。“关于”页显示构建版本，并提供项目主页和版本发布链接。底部的“退出程序”通过主循环正常退出 DeskIsle。

“顶部栏”页的三个预览与状态栏使用相同的背景绘制规则。栏高按 DIP 保存，变更后重新协商 AppBar 条带。开启沉浸模式时，从主屏前台最大化窗口的可见顶部取色，配合明暗文字绘制。右上角关闭按钮只对按下时选中且松手时仍处于前台的最大化窗口生效。托盘图标解锁时，应用层按系统拖动阈值区分排序与单击，通过注册身份跟踪按下的图标，并用稳定键保存顺序。显示、命中、通知区域位置查询和菜单锚点共用排序后的槽位。

“时间”页的预览选择保留在当前进程内。“监控”页的改动立即应用到顶栏并保存到设置文件。CPU、内存和磁盘卡片可切换条形、环形、曲线和数值样式，核心温度卡片可附加 GPU 温度。键盘聚焦这类卡片时，空格或回车切换主开关，左右键调整卡片内的选项。

“常规”页将界面缩放叠加到 Windows 的显示器 DPI，字体缩放单独用于 DirectWrite 的测量与绘制。面板提供简体和繁体中文，简繁转换仅用于面板文案。毛玻璃强度调节设置侧栏和关于卡片在 DWM 亚克力上的色调透明度。“屏幕刷新率…”打开 Windows 高级显示设置。温度单位只影响顶栏读数，采样仍保留摄氏值。

“Dock”页的图标间距、底部间距以 DIP 计。显示隐藏模式保存在 `dock.display_mode`。读取仅含旧 `dock.immersive` 的配置时，开启映射为自动隐藏，关闭映射为默认模式。自动隐藏使用主屏工作区最底部的整行像素唤出，智能隐藏使用其中 Dock 正下方的一段。`app/immersion.rs` 按配置的停留延迟展开 Dock，指针提前移出则取消。展开的窗口延伸到底边。指针停在窗口两侧的唤出区域时，通过单次计时器复查位置，方便用户沿底边移向图标。智能隐藏始终按展开时的 Dock 位置判断重叠。热键模式单独注册 Ctrl+Alt+D，退出该模式时释放绑定。

“常规”与“Dock”设置在提交改动时生效并保存。应用层逐项比较新旧设置：Dock 尺寸和间距改变时重新布局，悬停放大在下次悬停时生效，隐藏任务栏改变时立即隐藏或交还任务栏并重新计算工作区，开机启动写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。系统拒绝某项改动时报告错误，并把该项恢复为原值，其余改动照常生效。

任务栏快捷键由窗口注册，发生按键冲突时保留原绑定并提示。应用菜单仅在最近文件数量大于零且有显示空间时查询 Shell。`platform/shell/recent.rs` 使用目标窗口或固定快捷方式上的显式 AppUserModelID 读取最近文档列表，可打开的文件按 Windows 文件关联启动。未提供可用列表的应用沿用原菜单。

文件型设置以 `id = value` 逐行写入 `%APPDATA%\DeskIsle\settings.ini`，`#` 开头的行为注释。文件不存在时使用默认值。读取失败时提示并使用默认值；某一行无效时提示并只让该项回到默认值。用户再次修改时才覆盖文件。未知的键会被忽略，以兼容较新版本写入的文件，但下次保存时不会保留。开机启动的实际状态由注册表决定：启动时读取，只有指向当前可执行文件的启动项才算启用。

新增一项设置的步骤：

1. 在 `settings.rs` 的 `Key` 中加入变体，在 `SCHEMA` 中加入一行，写明 `id`、分组、说明、控件、默认值和存放位置。需要新分页时同时加入 `Section` 和 `SECTIONS`。需要给调用方用的类型值时，加一个访问方法。
2. 在 `app/settings.rs` 的 `apply_settings` 中处理该键变化后的效果。编译器会要求覆盖新变体。
3. 面板、文件读写、校验和恢复默认无需改动。`settings.rs` 的单测会检查 `id` 唯一、默认值合法以及读写往返一致。

## 职责与数据流

以点击 Dock 图标为例，平台把指针事件交给应用层。应用层用 UI 布局命中对应图标，重新枚举窗口，再用领域模块的 `group_apps` 和 `AppGroup::action` 决定动作。启动或激活交给 Shell 适配器，多窗口选择交给菜单。操作完成后，应用层刷新快照并把新布局和活动状态交给渲染器。

渲染器根据布局创建合成图层。图标内容或缩放密度变化时更新纹理，指针移动时只提交受影响图层的变换。静止且状态稳定时不安排重绘。

启动时先订阅窗口事件，再枚举可见的应用窗口。回调将变化投递到 UI 消息循环，由 UI 线程查询最新状态、更新应用分组，再向合成器提交变化。重复通知按当前窗口状态归并，前台标记以系统实际前台窗口为准。

点击图标时，按应用标识查找窗口。没有窗口则启动应用，单窗口直接切换，多窗口先供用户选择。执行前复核目标的存在性和应用身份，仅对已最小化窗口执行还原。若目标已关闭，刷新窗口列表。若系统拒绝激活，保留实际活动项。

## 资源与恢复

同一登录会话只运行一份 Dock。隐藏系统任务栏前，`platform/taskbar.rs` 将 Explorer 的进程号和任务栏窗口句柄写给恢复进程。释放底部条带前，Dock 也会将这项操作告知恢复进程。正常退出时 Dock 核对窗口归属，恢复任务栏及其底部占位，再释放会话互斥对象。主进程被强制终止时，系统会关闭管道，由恢复进程执行同一项还原。恢复进程持有独立的会话标记，使随后启动的 Dock 能等到桌面还原后再接管。若任务栏在启动前已被其他工具隐藏，Dock 只调整自身布局。

启动或重新定位时遇到 Explorer 正在重启，状态栏暂按请求的矩形定位，等新 Shell 发出 `TaskbarCreated` 后重新申请工作区。完成协商、将托盘宿主重新置顶后，DeskIsle 再通知应用注册图标。

创建 Dock 窗口的 UI 线程负责消息循环、COM 初始化和合成提交。窗口回调只投递需要的事件，避免在可重入调用期间持有可变状态。取得所有权的图标和系统资源按各自 API 契约释放。退出时先撤销事件订阅，再释放合成对象、销毁窗口，最后反初始化 COM。

布局以设备无关单位计算，定位和点击命中使用目标显示器的有效 DPI。收到 DPI、工作区或显示拓扑变化通知后，重新查询显示器。原显示器消失时回到主屏工作区。顶部条带只在 Shell 通知位置变化、显示器边界或 DPI 改变时重新协商，避免每次工作区通知都再次触发调整。Explorer 重启后重新注册 AppBar、把托盘宿主重新置顶并重新枚举窗口，应用随 `TaskbarCreated` 重新添加图标。前台变化后也会重新置顶托盘宿主，因为 Explorer 激活任务栏时会把它提到前面。所属窗口已关闭的托盘图标在窗口事件后移除。图形设备失效时保留应用状态，重建设备、表面和图层。若重建失败，报告失败的操作和系统错误码。

## 行为验证

用布局测试覆盖混合缩放、工作区偏移与图标命中边界。真机验证窗口选择期间目标关闭、最大化窗口切回、Explorer 重启和拔掉副屏后的行为。托盘部分验证图标增删与动态图标刷新、左右键菜单、隐藏设置跨重启保留，以及与其他占用顶部或托盘的桌面工具共存时的表现。分别记录静置时的 CPU 占用与连续悬停时的帧时间，并注明硬件、刷新率和缩放比例。
